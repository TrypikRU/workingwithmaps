# Geometry module

Чистый Dart без Flutter, geolocator и сторонних geometry-библиотек.
Общий импорт: `core/geometry/geometry.dart`. Существующий Haversine в distance.dart
оставлен без изменений; GeoPoint получил value equality и JSON-сериализацию.

## Circular geofence

`CircularGeofence(center: GeoPoint(...), radius: 50)` использует Haversine:
- inside: расстояние ≤ radius;
- approaching: radius < расстояние ≤ approachingRadius;
- outside: расстояние > approachingRadius.

По умолчанию radius=50 м, approachingRadius=3×radius (150 м). Можно задать оба порога.
Некорректные координаты, нечисловые/отрицательные радиусы и approachingRadius<radius
вызывают ArgumentError. На границах сравнение включительное, без округления до метров.

Riverpod objectGeofencesProvider применяет геометрию к объектам из repository.
Неизвестная/последняя известная позиция, отсутствие доступа и accuracy>50 м не дают
достоверного состояния. Карта показывает ненавязчивую подсказку, пока пользователь
находится в approaching; при выходе/inside она исчезает. При нескольких объектах
показывается первый в текущем порядке списка. Визиты не создаются автоматически.
Это информационные геозоны: существующая политика ручного Check-in не менялась.

## Point in Polygon

`isPointInPolygon(point, vertices)` либо `GeoPolygon(vertices).contains(point)`.
GeoPolygon удобно переиспользовать при многократных проверках одного контура.

Ray Casting проводит горизонтальный луч вправо и переключает чётность при каждом
пересечении ребра. Полуоткрытый диапазон Y предотвращает двойной учёт вершины;
горизонтальные рёбра не делят на ноль. Перед подсчётом пересечений проверяется
принадлежность отрезку — **граница и вершины считаются внутри**.
Погрешность границы 1e-10 градуса нужна только для floating point, не для GPS accuracy.

Поддерживаются простые выпуклые/вогнутые кольца, оба направления вершин, замыкающая
вершина может присутствовать или отсутствовать. Долгота разворачивается относительно
первой вершины для локальных контуров через ±180°. Контуры должны занимать менее
180° по долготе. Сложность проверки O(n). Пустые/коллинеарные/вырожденные контуры
и невалидные координаты отклоняются. Самопересечения, отверстия и сферические
геодезические рёбра не входят в контракт: это локальные простые контуры в координатах
longitude/latitude, не кадастровый геодезический инструмент.

## Хранение и карта

TechnicalObject содержит `polygon: List<GeoPoint>` и `geofenceRadius`.
Пустой список означает отсутствие polygon. Drift v5 добавляет objects.polygon
(JSON TEXT, default `[]`, PolygonConverter) и objects.geofence_radius (default 50).
Запись через ObjectsRepository.saveObject сохраняет геометрию вместе с объектом
и существующей queue operation атомарно. Невалидный polygon откатывает транзакцию.
Freezed/JSON-модель поддерживает round-trip; UI не получает Drift rows.

Текущий backend не имеет контракта polygon/radius: эти поля локальные и не входят
в ObjectDto. API refresh намеренно не перезаписывает их. Изменения объектов, включая
геометрию, пока не отправляются серверу (существующий object writer ещё не реализован).

PolygonLayer рисует сохранённые контуры с заливкой и границей цвета статуса объекта.
Для demo-1 добавлена синтетическая прямоугольная область. Seed использует её в пустой
БД; миграция добавляет её только demo-1 с исходными координатами. Пользовательские
объекты и перемещённые demo-объекты получают пустой контур. Это демонстрационные,
а не реальные границы территории. Редактор контуров на данном этапе не добавлялся.

Тесты: круговые пороги и точные границы; квадрат, треугольник, вогнутая L-форма,
вершины/рёбра, reverse/closed ring, линия смены дат, невалидные данные; JSON/SQLite
round-trip, миграция v4→v5, rollback и сохранение геометрии при API refresh; PolygonLayer
и появление/исчезновение approaching-подсказки при изменении GPS.
