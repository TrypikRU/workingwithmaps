# Геометрия

Чистый Dart без Flutter, geolocator и сторонних геометрических библиотек.
Общий импорт: core/geometry/geometry.dart. Haversine в distance.dart вычисляет
расстояние; GeoPoint поддерживает сравнение по значению и сериализацию JSON.

## Круговая геозона

CircularGeofence(center: GeoPoint(...), radius: 50) использует Haversine:

- inside — расстояние не больше radius;
- approaching — больше radius, но не больше approachingRadius;
- outside — больше approachingRadius.

По умолчанию radius равен 50 м, approachingRadius — трём радиусам, то есть 150 м.
Можно задать оба порога. Некорректные координаты, нечисловые или отрицательные
радиусы и approachingRadius < radius вызывают ArgumentError. Границы включаются
в сравнение без округления расстояния до метров.

Провайдер Riverpod objectGeofencesProvider применяет геометрию к объектам
репозитория. Неизвестная или последняя известная позиция, отсутствие доступа и
точность хуже 50 м не дают достоверного состояния. Подсказка карты появляется
при приближении и исчезает внутри зоны либо снаружи. Если объектов несколько,
показывается первый в текущем порядке списка. Посещения автоматически не создаются:
это информационные зоны, отдельные от правил ручной отметки.

## Точка в полигоне

Используйте isPointInPolygon(point, vertices) или GeoPolygon(vertices).contains(point).
GeoPolygon удобен для повторных проверок одного контура.

Ray Casting проводит горизонтальный луч вправо и меняет чётность при каждом
пересечении ребра. Полуоткрытый интервал Y предотвращает двойной учёт вершины;
горизонтальные рёбра не делят на ноль. Сначала проверяется принадлежность отрезку:
**граница и вершины считаются внутренними**.

Допуск 1e-10 градуса учитывает вычисления с плавающей точкой, а не погрешность GPS.
Поддерживаются простые выпуклые и вогнутые контуры в обоих направлениях обхода.
Замыкающая вершина необязательна. Для локальных контуров через ±180° долгота
разворачивается относительно первой вершины. Размах по долготе должен быть меньше
180°. Сложность O(n). Пустые, коллинеарные, вырожденные контуры и неверные
координаты отклоняются. Самопересечения, отверстия и сферические геодезические
рёбра не поддерживаются. Это не кадастровый геодезический инструмент.

## Хранение и карта

TechnicalObject содержит polygon: List<GeoPoint> и geofenceRadius.
Пустой список означает отсутствие контура. Схема Drift v5 добавляет
objects.polygon (JSON TEXT, по умолчанию [], PolygonConverter) и
objects.geofence_radius (по умолчанию 50).

ObjectsRepository.saveObject атомарно сохраняет геометрию, объект и исходящую
операцию. Неверный полигон откатывает транзакцию. Freezed/JSON поддерживает
сериализацию и обратное восстановление; интерфейс не получает строки Drift.

Сервер пока не передаёт polygon/radius: эти поля локальные и не входят в ObjectDto.
Обновление из API сохраняет их. Редактируемые поля объекта отправляются через PATCH,
но геометрия в запрос не входит.

PolygonLayer рисует контуры с заливкой и границей цвета статуса. Для demo-1
(«Тепловой пункт № 1») задан условный прямоугольник. Он добавляется с начальными
данными в пустую БД; миграция добавляет его только неизменённому учебному объекту.
Пользовательские и перемещённые объекты получают пустой контур. Это учебная
граница, а не реальная территория. Редактора контуров пока нет.

Тесты проверяют круговые пороги, точные границы, квадрат, треугольник, вогнутую
L-форму, вершины и рёбра, направления и замыкание контура, линию смены дат,
неверные данные, сохранение и восстановление через JSON/SQLite, миграцию v4→v5,
откат и сохранность геометрии при обновлении API, PolygonLayer и подсказку о приближении.
