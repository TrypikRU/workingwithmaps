# Офлайн-карты

Команды выполняются из корня репозитория.

## Отдельное хранилище тайлов

**Локальные бизнес-данные и сохранённая подложка карты - разные механизмы.**
Объекты, обходы, посещения, GPS-точки и sync_queue работают через Riverpod,
репозитории, Drift и общий SyncEngine. Загрузка карты не меняет схему, правила
конфликтов и фоновую синхронизацию. Для отметки о посещении карта не требуется.

Кнопка **«Офлайн-карта»** в верхней панели открывает фиксированный регион:
Сыктывкар, район ЖД вокзала. Границы:
[50.786, 61.654, 50.807, 61.665] - запад, юг, восток, север.
В MVP **40 тайлов** при масштабе **13–16**. Кнопка **«Офлайн-регион»**
вписывает сохранённую область в экран. Полигоны, маркеры, GPS и маршрут остаются
независимыми слоями.

Все пять учебных объектов находятся внутри региона.
Идентификатор пакета - `syktyvkar-railway-v1`.
Готовый пакет [field-region.json](../tools/offline_maps/output/field-region.json)
включён в репозиторий. Это растровая карта, подготовленная из данных OSM
с оформлением в QGIS. Исходные PBF и MBTiles для её использования не нужны.
Пакет не встроен в APK: приложение загружает его с отдельного статического сервера.
На карте показана одна атрибуция «© OpenStreetMap contributors».

## Загрузка готового пакета

Нужен Python 3, без дополнительных библиотек. Проверьте `python --version`:
ожидается номер версии, а не одиночное слово `Python`. Если Windows запускает
псевдоним вместо интерпретатора, установите Python или укажите полный путь
к `python.exe`. Все команды ниже выполняются из корня репозитория.

~~~powershell
python -m http.server 8090 --bind 0.0.0.0 --directory tools/offline_maps/output
~~~

Оставьте терминал открытым. Сервер публикует только каталог пакетов.
Это отдельный процесс; ASP.NET Core API на порту 5080 не отдаёт карту.
`API_BASE_URL` не меняет адрес загрузки карты - для него нужен `OFFLINE_MAP_PACK_URL`.

### Эмулятор

Адрес пакета по умолчанию - `http://10.0.2.2:8090/field-region.json`.

~~~powershell
flutter run --debug -d <android-device-id> --dart-define=API_BASE_URL=http://10.0.2.2:5080/ --dart-define=OFFLINE_MAP_PACK_URL=http://10.0.2.2:8090/field-region.json
~~~

### Телефон по USB

~~~powershell
adb reverse tcp:8090 tcp:8090
adb reverse tcp:5080 tcp:5080
flutter run --debug -d <android-device-id> --dart-define=API_BASE_URL=http://127.0.0.1:5080/ --dart-define=OFFLINE_MAP_PACK_URL=http://127.0.0.1:8090/field-region.json
~~~

При нескольких устройствах добавьте `-s <android-device-id>` к `adb`.
Оба сервера должны быть запущены на ПК.

### Телефон в локальной сети

ПК и телефон должны находиться в одной локальной сети. Узнайте IPv4 ПК через
`ipconfig`; замените пример `192.168.46.166` своим адресом.
Разрешите порт 8090 в брандмауэре для доверенной частной сети. При необходимости
выполните в PowerShell от имени администратора:

~~~powershell
New-NetFirewallRule -DisplayName "Полевой инспектор - пакет карты" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8090 -Profile Private -RemoteAddress LocalSubnet
~~~

В [network_security_config.xml](../android/app/src/debug/res/xml/network_security_config.xml)
добавьте адрес ПК в существующий `domain-config`, без протокола и порта:

~~~xml
<domain includeSubdomains="false">192.168.46.166</domain>
~~~

На телефоне откройте `http://192.168.46.166:8090/field-region.json` в браузере:
он должен показать или скачать JSON. Для API отдельно выполните
[настройку локальной сети](../backend/README.md#реальное-устройство-android-в-локальной-сети).
Затем полностью остановите предыдущий запуск Flutter и запустите:

~~~powershell
flutter run --debug -d <android-device-id> --dart-define=API_BASE_URL=http://192.168.46.166:5080/ --dart-define=OFFLINE_MAP_PACK_URL=http://192.168.46.166:8090/field-region.json
~~~

XML и `--dart-define` применяются при новой сборке, а не горячей перезагрузке.
На карте нажмите «Офлайн-карта» → «Скачать регион». Для замены уже установленного
пакета используйте «Обновить пакет». Кнопка «Офлайн-регион» показывает покрытие.
HTTP предназначен для отладки; в выпускной сборке используйте HTTPS.
Пакет загружается одним GET без перенаправлений и параметров запроса.

### Если загрузка не работает

- `/objects` открывается, а пакет нет: проверьте отдельный сервер на порту 8090,
  брандмауэр и наличие `field-region.json` в публикуемом каталоге.
- Браузер открывает пакет, приложение нет: проверьте `OFFLINE_MAP_PACK_URL`,
  разрешение HTTP для IP компьютера и полностью перезапустите отладочную сборку.
- Сервер отвечает 404: проверьте текущую папку терминала и `--directory`.
- Прежняя карта остаётся после ошибки: это ожидаемо; неполный или повреждённый
  пакет не заменяет рабочий. Проверьте формат, полноту и лимиты ниже.

## Подготовка нового пакета

Для запуска используется готовый пакет. Этот раздел нужен при изменении карты.
Нужен растровый MBTiles с PNG 256×256, покрывающий регион на масштабах 13–16.
Исходный `.osm.pbf` содержит геометрию и теги, а не готовые изображения;
приложение не читает его непосредственно. Векторные тайлы PBF и JPEG не поддерживаются.

При экспорте локальных слоёв в QGIS используйте «Generate XYZ tiles (MBTiles)»,
PNG, масштабы 13–16 и область с запасом: запад 50.77, восток 50.83,
юг 61.64, север 61.68. В поле области QGIS с EPSG:4326 порядок значений:
`50.77,50.83,61.64,61.68` - минимум X, максимум X, минимум Y, максимум Y.
Запас нужен для покрытия тайлов, пересекающих границу региона.
Оформление текущих локальных слоёв попадёт в экспортируемые изображения.

~~~powershell
python tools/offline_maps/prepare_pack.py "C:/maps/syktyvkar.mbtiles" --rights-confirmed --attribution "© OpenStreetMap contributors"
~~~

Утилита читает фиксированные координаты MBTiles, преобразует TMS в XYZ
(или учитывает `metadata.scheme=xyz`), проверяет полноту и создаёт
`tools/offline_maps/output/field-region.json`. Сетевых запросов нет.
Успешный результат содержит `Prepared 40 tiles`. Ошибка `Missing tile`
означает неполное покрытие: проверьте масштабы и область экспорта.
Даже из MBTiles всего города извлекается только район ЖД вокзала.

Готовый `field-region.json` разрешён в `.gitignore`; остальные результаты
в `output` игнорируются. Исходные PBF и MBTiles в репозиторий добавлять не нужно.
Атрибуцию данных и требуемых авторов стиля указывайте при подготовке пакета.
`--rights-confirmed` подтверждает проверку прав, но не заменяет лицензию.

Общедоступный `tile.openstreetmap.org` запрещает предварительную и массовую
загрузку для использования без сети. Для пакета используйте собственную
отрисовку или источник с правом использования без сети и распространения.
[Политика сервера](https://operations.osmfoundation.org/policies/tiles/).

## Выбор источника

OfflineFirstTileProvider сначала ищет точный z/x/y в установленном пакете.
Найденный тайл отображается без HTTP при любом состоянии сети. Иначе используется
NetworkTileProvider из flutter_map с HTTP-кэшем и указанием авторства OSM.
Наличие Wi-Fi не считается доказательством доступа к интернету.
Ошибка сети вне покрытия оставляет пустую подложку; объекты и маршрут доступны.
Сохранённые тайлы не обновляются из сети автоматически.

Переключатель **«Только сохранённая карта»** полностью запрещает обращение к сети
на время текущего запуска. При установленном пакете maxNativeZoom равен 16:
масштаб 17–19 увеличивает сохранённые изображения без загрузки новых деталей.
Ниже масштаба 13 и вне покрытия подложка без сети не гарантируется.
HTTP-кэш может содержать дополнительные тайлы, но не считается скачанным регионом.
**«Обновить карту»** повторяет загрузку видимого слоя после восстановления сети;
**«Обновить пакет»** явно заменяет сохранённый регион.

## Хранение, ограничения и восстановление

Путь: getApplicationSupportDirectory()/offline_maps/region.json.
Drift, sync_queue и WorkManager не используются.
Формат xyz-png-v1 содержит region, offlineAllowed, attribution и словарь
z/x/y → PNG в base64. Для 40 тайлов это простой переносимый контейнер;
flutter_map получает PNG через MemoryImage. Дополнительная библиотека архивов
и чтение MBTiles непосредственно в Flutter не нужны.

Лимиты: 12 МиБ JSON, 8 МиБ PNG суммарно, 256 КиБ на тайл, строго PNG 256×256
и полный набор из 40 ключей. Поток ограничивается по фактически полученным байтам.
Ожидание соединения - 10 секунд, получения данных - 20 секунд, всей загрузки -
2 минуты. Одновременные загрузки объединяются.

Изображения последовательно декодируются и проверяются до установки.
Готовый пакет записывается во временный файл с принудительной записью на диск,
затем переименовывается. При ошибке прежний пакет сохраняется; файл .tmp после
аварии не активируется. После перезапуска активный пакет читается с диска.
Докачки нет: повтор скачивает небольшой файл заново. Удаление приложения или
очистка данных удаляют и пакет.

В памяти хранится ограниченный набор сжатых PNG; декодированные изображения
кэширует Flutter. Установка и смена режима сбрасывают только TileLayer через
поток сброса. MapController, маркеры, полигоны и линия маршрута не пересоздаются.

## Проверка

~~~powershell
python -m unittest discover -s tools/offline_maps -v
flutter test test/features/map/offline_map_test.dart
flutter analyze
flutter test
~~~

Тесты проверяют TMS→XYZ, полноту и размеры, запрет загрузки пакетов с адресов OSM,
установку, замену, перезапуск, сохранение старого пакета при ошибке, отсутствие
запросов для локальных тайлов и переход к сети только при их отсутствии.
Тестовые изображения нейтральные, без картографических данных.

Для ручной проверки запустите сервер готового пакета, скачайте регион, нажмите
«Офлайн-регион», включите авиарежим и перезапустите приложение. Тайлы региона,
маркеры и маршрут должны остаться. После включения сети вне покрытия снова
доступен OSM. Права и детализация пакета зависят от его источника.
